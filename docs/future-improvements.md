# 후속 개선사항

## 종목 검색 속도 및 입력 UX — 구현 완료 (2026-10-06)

- 종목 목록을 프로세스 메모리에 캐시합니다. 정상 목록은 원본의 24시간 갱신 주기를 따르고, 외부 목록 갱신 실패로 기존 목록을 사용하면 60초 후 다시 시도합니다. 서버 재시작 시 처음 한 번은 Firestore를 읽습니다.
- 입력 후 300ms 동안 추가 입력이 없으면 자동 검색합니다. 검색 버튼·Enter·더 보기도 유지합니다.
- 입력 변경 즉시 이전 요청을 취소하고 늦은 응답·오류를 무시합니다. 로그아웃 시 타이머와 요청을 정리합니다.
- 검색 중 상태를 표시하며, 종목 목록 잠금과 가격 갱신 잠금을 분리합니다.
- 캐시를 채운 후 반복 검색에는 종목 목록의 Firestore 읽기가 없습니다. 요약·기록·대화 등 다른 읽기는 계속 필요합니다.

검증용 2,590개 종목과 메모리 저장소로 기존 커밋 `145bda0`과 변경 코드를 비교했습니다. 워밍업 후 검색 50회의 저장소 읽기 호출은 100회에서 0회, 로컬 응답 중앙값은 4.909ms에서 0.495ms였습니다. Firestore 네트워크와 Render 콜드스타트를 포함한 실제 서비스 속도 측정은 아니며 운영 확인이 별도로 필요합니다.

## 남은 개선사항

- 운영 Render 환경의 첫 검색·반복 검색 응답 시간 측정
- 실시간 현재가: 별도 시세 공급원·갱신 주기 설계 필요
- 다른 시장 확장: 국내 시장 검증 후 진행
